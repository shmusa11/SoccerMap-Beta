Processing detail

Fast mode chooses its own sampling, enhancement and player detection. Stride, ball cadence, player toggle and field-condition controls below apply to classic mode. A saved camera setup also uses classic mode.

Off by default. In fast mode only, enabling this sends sampled video frames to OpenAI using your own API key, with a $0.30 per-run budget. Leave it off to process footage locally after model setup.

Uses the CPU and smaller player images, one frame at a time. Slower, with less detail for distant players. Runs stop if memory gets too low.

    From film to field coordinates.

    SoccerMap estimates a pitch plane, detects players and renders the positions that can be mapped. It is a research prototype for short clips, not a full-match analysis service.

    What the demonstration shows

    The synthetic demo is generated locally. It contains invented players and a deliberate mapping gap from 18 to 24 seconds. It demonstrates controls, cancellation, missing-data handling, analytics and exports. It does not measure computer-vision accuracy or speed.

    What real analysis does

    Uploaded footage runs through the existing calibration and detection pipeline. Low coverage, uncertain teams and missing ball detections remain possible. Save a camera setup by placing four points, then reuse it while the image view matches. Full-match accuracy and speed still need evaluation.

    Local storage

    Imported copies and results stay in .soccermap/ on this computer, including unsaved runs. They are excluded from Git. Closing the browser does not delete them. Saving adds a reference in Saved analyses.
